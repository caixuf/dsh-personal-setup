# 新机器复刻清单 —— 从零到能用手机遥控

> **一句话**：clone 三个仓库 → 跑一条安装脚本 → 手工填三处占位符 + **配 `dsh-sync`** → 重启 DSH。
>
> 详细原理见 `intent/dsh.md`；本文件只回答「换台电脑，按什么顺序敲什么」。

## 0. 前置

- Windows + PowerShell（**必须是 PowerShell 5.1/7 的 pwsh.exe 正常版**，不要用 ISE 内置宿主）
- 已装 DSH Desktop
- 三个仓库放在**同一目录**下（脚本靠相邻关系发现源码）：

```
<你的工作区>/
├─ dsh-personal-setup/    ← 本仓库
├─ dsh-native-mobile/     ← git clone https://github.com/caixuf/dsh-native-mobile.git
└─ dsh-rea/               ← git clone https://github.com/caixuf/dsh-rea.git
```

> 也可以放在 `~/Downloads/aiwork/` 下，脚本同样能发现。

## 1. 装 DSH 环境（一条命令）

```powershell
cd dsh-personal-setup
Set-ExecutionPolicy -Scope Process Bypass -Force
.\scripts\install-dsh.ps1 -DryRun     # 先看它要干什么（纯只读，不写任何文件）
.\scripts\install-dsh.ps1             # 真装
```

脚本会做四件事：
1. 装 **16 个公共 npm bundle**（含 `dsh-bot-gateway`、`dsh-mnemon`、`dsh-sync`…）；
2. **从本地源码**装 2 个自研宿主插件（`dsh-mobile-gateway`、`dsh-rea`）——
   它们没发 npm，走 `dsh plugin add` 会 404；
3. 写 `<dsh-home>/cordis.patch.yml`（机器级补丁，三行宿主插件）+ 复制机器级 node_modules；
4. 备份现有 profile（`-DryRun` 时**完全只读**，不写任何文件）。

> ℹ️ **公共 npm 包数 = 模板 `dependencies` 里非自研的条目**。
> 模板共 18 条依赖，其中 2 条是自研本地源码装（`dsh-mobile-gateway` / `dsh-rea`），
> 故公共 npm 为 16 个。脚本会实时打印「共 N 个公共包 / M 个本地插件」，
> **以它打印的数字为准**（模板增删插件后本行可能滞后）。

## 2. 重启 DSH

**必须重启**：Node ESM 不热重载，patch 改动也要重启才读盘。
（DSH 运行中改 `cordis.patch.yml` 会让设置写入的 revision 乐观锁错位。）

## 2.5 桌宠是可选项（默认在 bundles 里）

模板 `bundles` 含 `dsh-whale-girl-pet`，装完会有鲸鱼娘桌宠。
不想要就把它从 `package.json` 的 `dsh.profile.bundles` 里删掉再重启。
（本机 2026-10-13 起就是关闭状态；包仍在 `dependencies`、`node_modules` 里完好 70/70。）

## 2.6 🔴 配 `dsh-sync`（**这一步不做，装了也永远不同步**）

> **2026-10-14 补**：此前本清单 0～6 步里**根本没有这一步** ——
> 照它走完会得到一台"装好了插件、面板也在，但 repoUrl/token 全空、同步永不触发"的机器。
> `install-dsh.ps1` 对 `dsh-sync` **0 处引用**，`apply.sh` 只会**警告**"覆盖会丢 token"、不会帮你填。

**判据**（插件源码 `gitProtocolOn()`）：`gitEnabled && repoUrl && token` 三者**全非空**才触发同步。

在 **设置 → 插件 → dsh-sync → Git 页签**填：

| 字段 | 值 |
|---|---|
| 仓库托管方 | **GitHub**（默认是 GitCode，要点按钮切过去） |
| owner | `caixuf` |
| repo | `dsh-sync` |
| branch | `main` |
| access token | **自己生成**，见 `intent/dsh-sync-配置清单.md` 的「token 怎么生成」 |

⚠️ **不要**从旧机拷 `~/.dsh/dsh-sync/settings.json`（含明文 token，且会覆盖新机身份）。

**配完必须验证**（只"看着有值"不算）：

```powershell
# ① 设置真的落盘了（persist.fileOk 应为 true —— 只写进宿主 patch 是不够的）
Get-Content "$env:USERPROFILE\.dsh\dsh-sync\settings.json"

# ② 真正跑一次同步后，state.json 里不该再有 pullError
Get-Content "$env:USERPROFILE\.dsh\dsh-sync\state.json" -Raw
```

⚠️ **GitHub 托管的功能边界**（换机时最容易误判成"坏了"）：
插件在 GitHub 上是**"只推分支"降级模式** —— 每次同步只推一个
`sync/<实例ID>/<时间戳>` 分支，**PR 创建/合并、`conflict/run`、`prune-branches` 全是 GitCode 专属**，
所以 **`main` 不会自动前进**，要**人工在网页开 PR 合并**。
且 token 会被提交进那个私有库（`cordis.patch.yml` 在同步范围内）。
详见 `intent/dsh-sync-配置清单.md` 的「GitHub 托管的功能边界」与「token 随提交入库」两节。

**频率**：保持 `intervalMinutes: 1440`（一天一次）。插件**每次同步都新建一个分支**，
30 分钟一次 = 48 个分支/天；一天一次才可控。

## 3. 打通公网（这一步换机最容易漏）

DSH 默认只监听本机，手机在外面连不上。需要 **VPS 侧 FRP + Caddy** + **家里客户端 frpc**。

### 3.1 VPS 侧（新 VPS 一条命令）

```bash
# 传到 VPS 上执行
FRP_TOKEN='<你的令牌>' VPS_IP='<VPS公网IP>' bash provision-vps.sh
```

它会装 frps、写配置、注册服务、装 Caddy 白名单（**含封死管理面**）、配 ufw。
细节与安全设计见 `templates/dsh/caddy/README.md`。

> ⚠️ **云厂商安全组也要放行** `7000/tcp` 和 `2444/tcp`（ufw 之外还有一层，脚本管不到）。
> **不要**放行 `2443/tcp`。

### 3.2 家里客户端

1. 拿 `frpc.exe`（frp 官方或从旧机器拷）放到一个目录，比如 `~/Downloads/android-toolchain/`；
2. 把模板 `templates/dsh/frpc.toml` 复制成 `frpc.toml`，与 `frpc.exe` 同目录；
3. **填三处占位符**：
   - `serverAddr` = VPS 公网 IP
   - `auth.token` = 与 VPS 上 frps 一致的 token（**不要提交进 git**）
   - `remotePort` = 2443（必须与 frps 的 `allowPorts` 一致）
4. 运行 `.\frpc.exe -c .\frpc.toml`，日志出现 `start proxy success` 即通。

### 3.3 🔴 两个守护（不做的话「莫名其妙就连不上」）

`frpc` **不是 Windows 服务**，只是 Startup 文件夹里一个 `.cmd` 拉起的普通进程，
会**静默退出**；局域网桥同理。两者都要配「每 2 分钟检查一次」的计划任务兜底，
否则表现是「昨天还好，今天手机一直重连中，而且没有任何报错」。

🔴 **任务动作必须经 `wscript + run-hidden.vbs`，不能直连 `.cmd`。**
Windows 11 把 console 程序托管进 Windows Terminal，计划的 `<Hidden>true</Hidden>`
只对传统 conhost 生效 —— 直连 `.cmd` 的结果是**每 2 分钟弹一个 WT 窗口**。

```powershell
$dir = 'C:\path\to\scripts'          # frpc.exe / frpc.toml / *.cmd / run-hidden.vbs / start-hidden.mjs 都在这里
$vbs = "$dir\run-hidden.vbs"

$tasks = @(
  @{ Name = 'DSH-FRP-Tunnel-Guard'; Cmd = "$dir\frpc-guard.cmd" },
  @{ Name = 'DSH-LAN-Bridge-Guard'; Cmd = "$dir\dsh-lan-bridge-guard.cmd" }
)
foreach ($t in $tasks) {
  $action  = New-ScheduledTaskAction -Execute 'wscript.exe' -Argument "`"$vbs`" `"$($t.Cmd)`""
  $atLogon = New-ScheduledTaskTrigger -AtLogOn
  $every2  = New-ScheduledTaskTrigger -Once -At (Get-Date) `
               -RepetitionInterval (New-TimeSpan -Minutes 2) `
               -RepetitionDuration ([TimeSpan]::MaxValue)
  $settings = New-ScheduledTaskSettingsSet -MultipleInstances IgnoreNew `
                -ExecutionTimeLimit (New-TimeSpan -Minutes 5) -Hidden
  Register-ScheduledTask -TaskName $t.Name -Action $action `
    -Trigger $atLogon, $every2 -Settings $settings -Force
}
```

> 两个脚本都是**幂等**的：已在跑就直接 `exit 0`，重复触发不会堆进程。
>
> 🔴 **`start-hidden.mjs` 必须与两个 `.cmd` 同目录** —— 守护内部拉常驻进程靠它
> （`start "" /min` 只最小化窗口，会留下一个真窗口，见 `templates/dsh/README.md`
> 的「弹窗两层根因」）。脚本用 `%~dp0` 自定位，放哪都行，只要与 `.cmd` 同处。

### 3.3.5 🔴 DSH 本体自启（不做的话重启后手机连到死端口）

DSH **不在任何自启动项里**。重启后 frpc 和 LAN 桥都起来了，但 19387 没人监听，
手机端连的是个死端口。

```powershell
$ws  = New-Object -ComObject WScript.Shell
$lnk = $ws.CreateShortcut("$env:APPDATA\Microsoft\Windows\Start Menu\Programs\Startup\DeepSeek Harness.lnk")
$lnk.TargetPath       = "$env:LOCALAPPDATA\Programs\DeepSeek Harness\DeepSeek Harness.exe"
$lnk.WorkingDirectory = "$env:LOCALAPPDATA\Programs\DeepSeek Harness"
$lnk.Description      = 'DeepSeek Harness (start at login so the mobile gateway port is alive)'
$lnk.Save()
```

> DSH 有 `requestSingleInstanceLock`，重复启动会立刻 `exit 0`，不会开第二份 ——
> 所以放 Startup 里是安全的，即使你手动又开一次。
> 它**没有** `--hidden`/`--silent` 参数，开机后正常显示主窗口，静默进托盘当前做不到。

### 3.4 局域网桥（0.2.1 起必需）

DSH 0.2.1 **禁止 webserver 绑 `0.0.0.0`**，而手机 App 配对时记的是
`http://<lan-ip>:19387`，所以**在家也连不上**（不只是外面）。
靠 `templates/dsh/lan-bridge/dsh-lan-bridge.mjs` 在具体网卡上监听同端口转发到回环。
详见该目录 README。

**自检**：

```powershell
# 本机：公网入口通不通
curl.exe -sk --noproxy '*' https://<VPS_IP>:2444/mobile-gateway/health
# 期望：{"ok":true,"service":"dsh-mobile-gateway",...}

# 本机：局域网桥通不通（-NoProxy 必加）
(Invoke-WebRequest 'http://<lan-ip>:19387/mobile-gateway/health' -UseBasicParsing -NoProxy).StatusCode
# 期望：200

# VPS 上：只读体检（不改任何东西）
bash provision-vps.sh --verify
```

> ⚠️ `--noproxy '*'` 必须加：本机全局代理会让「连不通」看起来「连得通」，
> 也让真实失败路径被掩盖（见 `intent/wsl.md` 同类坑）。
>
> ⚠️ 访问 `https://<VPS_IP>:2444/mobile-gateway/manage` 得到 **404 是正确行为** ——
> 管理面必须在 Caddy 最外层封死，因为 FRP 隧道会让 DSH 误判公网请求为回环。

## 已知会踩的坑（都实测过）

| 坑 | 症状 | 处置 |
|---|---|---|
| `.ps1` 存成无 BOM 的 UTF-8 | 中文吞引号 → `ParseError: 缺少右花括号` | 存成**带 BOM** 的 UTF-8；本仓库脚本已是 |
| `.cmd` 里写中文注释 | 报 `xxx 不是内部或外部命令` | `.cmd` 一律**纯 ASCII** |
| 巡检脚本默认重置密码 | 紧接着的脚本报 `mismatch`，看着像功能坏了 | 现在默认只读，要改加 `--reset-credentials` |
| 脱敏把判定逻辑一起换掉 | `publicMode` 对真实公网恒 false | 判定要依赖**结构特征**，别依赖具体 IP |
| DSH 运行中改 patch | ~~设置保存全部被拒（revision 乐观锁）~~ | ✅ **2026-10-18 实测更正**：0.2.1 的 settings revision 按**内存实时配置**算，外部改 patch 不会打歪。实测改 `<dsh-home>/cordis.patch.yml` 后 `/bot-gateway/` 从 200→404、主进程启动时间不变（Loader 热重载）。**但改完仍建议重启**：热重载只覆盖 patch 变化，Node ESM 的插件代码改动不会热加载 |
| **`start "" /min` 拉常驻进程** | 任务结果一直是 0，但任务栏常挂一个控制台窗口（frpc） | 用 `start-hidden.mjs`（`windowsHide`）。判据看 `MainWindowHandle=0` 且无 conhost 子进程 |
| **计划任务直连 `.cmd`** | 每 2 分钟闪一个 Windows Terminal 窗口 | 动作改 `wscript.exe run-hidden.vbs <cmd>` |
| **只看任务退出码当「修好了」** | 常驻窗口一直存在却以为已修 | 判据要用 `EnumWindows` 按 pid 枚举 + `MainWindowHandle`，不是 `LastTaskResult` |
| **一层转发让回环校验失真** | LAN 上管理面免鉴权 200（`remoteAddress` 恒 127.0.0.1） | 围栏建在桥上（`lan-bridge` 已内置 `/mobile-gateway/manage` 403）；别只信 `remoteAddress` |
| **`bot-gateway` 的 disabled 写在 profile 层** | 配置写着禁用、`/bot-gateway/` 仍 200 | 必须写**机器级** patch（home 层最后应用，会覆盖 profile 层） |
| **`dsh-sync.syncSettings` 开着** | 以为设置已备份，实际 `settings.yaml` 不存在、静默跳过 | 设 `false`；真正的设置源由 `plugins` 组覆盖 |
| **重启后手机连不上，但 frpc/桥都在** | DSH 本体不自启，19387 无人监听 | 按 **3.3.5** 把 DSH 放进 Startup |
| **装完不配 `dsh-sync`** | 插件 active、面板在，但 repoUrl/token 全空 → **同步永不触发**，毫无报错 | 按第 **2.6 步**在面板填 owner/repo/token；判据 `gitEnabled && repoUrl && token` 全非空 |
| `branch: main` 但远端没有 `main` | `pullError: couldn't find remote ref main`，"拉回来"永久失效 | ✅ 2026-10-14 已建 `main` 并设为默认分支（详见 `intent/dsh-sync-配置清单.md`） |
| 以为 GitHub 会像 GitCode 一样自动合并 | 远端堆了一串 `sync/*` 分支、`main` 不动 | GitHub 是**只推分支**降级模式，**要人工开 PR 合并**；非故障 |
| 同步频率设太低 | 30 分钟一次 → 48 个 `sync/*` 分支/天 | 保持 `intervalMinutes: 1440` |
| 照抄旧机的 `~/.dsh/dsh-sync/settings.json` | 明文 GitHub token 被复制到新机 | ❌ 别拷，在新机面板重填 |
| 以为 WSL fork 还在 | 用户级 skill 不加载（只出项目级） | 🔴 本机已回滚成官方版；要 fork 得按 `forks/dsh-wsl-workspace/README.fork.md` 重建并跑哨兵 |
