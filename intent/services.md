## 1. litellm 模型网关（4001）

**用途**：把多个 provider（commandcode / Cline / Copilot 等）统一成一个 OpenAI 兼容端点。

| 项 | 值 |
|---|---|
| 配置 | `~/.config/litellm/config.yaml`（12 KB，**无硬编码密钥**，用 `os.environ/`） |
| 密钥 | `~/.config/litellm/proxy.env`（❌ 不入库） |
| venv | `~/.local/share/litellm-venv/` |
| 数据 | `~/.config/litellm/github_copilot/`（令牌，不入库） |

**⚠️ `config.yaml` 是生成物**：头部写着
```
# GENERATED by bridge/render_config.py — DO NOT EDIT.
# Source of truth: registry/models.yaml + registry/profiles.yaml
# Regenerate:  ccp render
```
**所以不要手改 `config.yaml`** —— 改源头（`registry/*.yaml`）再 `ccp render`。

**恢复步骤**：
```bash
# 1. 建 venv 并装 litellm
python3 -m venv ~/.local/share/litellm-venv
~/.local/share/litellm-venv/bin/pip install 'litellm[proxy]'

# 2. 配置（模板无密钥，可直接用）
mkdir -p ~/.config/litellm
cp templates/litellm/config.yaml ~/.config/litellm/config.yaml

# 3. 【手动】创建 proxy.env（见 secrets.md）
chmod 600 ~/.config/litellm/proxy.env

# 4. 启动
~/.local/share/litellm-venv/bin/litellm --config ~/.config/litellm/config.yaml --port 4001
```

**验证**：`curl -s http://127.0.0.1:4001/models -H "Authorization: Bearer <key>" | jq '.data[].id'`

## 2. ccp — 终端 LLM 环境统一管理

**用途**：切换 Claude Code / 各 CLI 的 provider 环境变量，避免在 `.bashrc` 里硬编码。

### ✅ 它有自己的仓库（**不要复制本仓库的内容**）

| 项 | 值 |
|---|---|
| **仓库** | **https://github.com/caixuf/claude-code-providers** |
| 本地克隆 | `~/code/claude-code-providers` |
| 分支 / 提交 | `main` / `6976456`（2026-10-09） |
| 一键安装 | `bash install.sh`（还有 `--bridge` 选项） |

**新机装法**：

```bash
git clone https://github.com/caixuf/claude-code-providers.git ~/code/claude-code-providers
cd ~/code/claude-code-providers
bash install.sh            # 装 ccp 到 ~/.local/bin + 初始化 ~/.claude/providers
# 若要 OpenAI / CommandCode / ClinePass 模型：
bash bridge/setup_bridge.sh
```

`install.sh` 会：
1. 把 `bin/ccp` 复制到 `~/.local/bin/ccp`
2. 检查 PATH 并提示（我们的 `templates/profile.d/` 已含此行）
3. 用 `providers/*.json.example` 初始化 `~/.claude/providers/`（**已存在的文件不覆盖**）
4. 归档废弃 profile 到 `~/.claude/providers_disabled/`

### 该仓库的密钥处理（规范，值得信赖）

`.gitignore` 已正确排除：

```gitignore
providers/*.json              # 真实 profile（含密钥）不入库
!providers/*.json.example     # 只留模板
bridge/config.yaml            # bridge 配置（含密钥）不入库
!bridge/config.example.yaml
```

**所以新机 clone 后只需填 `providers/*.json` 里的密钥**，不会继承旧机密钥。

### 目录与状态

| 项 | 值 |
|---|---|
| 可执行 | `~/.local/bin/ccp`（由 `install.sh` 从仓库 `bin/ccp` 复制） |
| 仓库 | `~/code/claude-code-providers` |
| 配置 | `~/.ccp/config.json` |
| 状态 | `~/.ccp/state.json` |
| 生成物 | `~/.ccp/env.sh`（**由 `ccp use` 生成，勿手改**） |
| 密钥 | `~/.ccp/secrets.env`（❌ 不入库） |
| profiles | `~/.claude/providers/*.json`（❌ 含密钥，不入库） |

**关键路径发现**：`ccp` 的 `sync_providers()` 按以下顺序查找仓库
（`CCP_REPO_DIR` 环境变量可覆盖）：

```
1. $CCP_REPO_DIR
2. $(dirname ~/.local/bin/ccp)/..        # 即 ~/.local
3. ~/code/claude-code-providers          # ← 命中
4. ~/.claude-code-providers
5. ~/claude-code-providers
```

**所以仓库必须放在 `~/code/claude-code-providers`**，否则 `ccp sync` 失效。

### 用法

```bash
ccp                        # 列出所有 provider（* 标记当前）
ccp <provider> [model]     # 切换 provider
ccp -c / --current         # 查看当前 provider / model / 端点
ccp -r [N]                 # 回滚到第 N 个最近备份
ccp -t [name]              # 快速测试（ping）
ccp sync                   # 与仓库模板同步 profile
ccp bridge <action>        # 本地 bridge 管理（status/restart/start/stop/logs）
ccp auth copilot           # Copilot 设备流认证
```

**当前 active**（实测）：`cmdc-deepseek-fast`（model `cmdc-deepseek-fast[1m]`）

**可用 provider 清单**（实测）：`cline-deepseek`、`cmdc-deepseek-fast`、`cmdc-deepseek-pro`、
`cmdc-deepseek`、`cmdc-vision`、`copilot`、`deepseek`、`minimax`

### `env.sh` 生成的内容（指向本地 litellm 4000）

```bash
export ANTHROPIC_API_KEY=sk-ccp-local     # ← 本地占位 key，非真实密钥
export ANTHROPIC_BASE_URL=http://127.0.0.1:4000
export ANTHROPIC_MODEL=deepseek/deepseek-v4.1-flash
```

⚠️ `ccp` 脚本自身**经检查不含任何密钥**（0 命中高置信特征），可安全经由其仓库分发。

**⚠️ 依赖关系**：`ccp` → 需要 litellm(4001) 起着 → 需要 `proxy.env` 的密钥。
三者顺序不能反。

## 3. IMFL 自动测试云平台（9900）

| 项 | 值 |
|---|---|
| 单元 | `/etc/systemd/system/imfl-autotest.service` |
| 代码 | `~/code/imfl_auto_test` |
| 环境 | `~/code/imfl_auto_test/.env`（`EnvironmentFile=-`，**可选**） |
| 依赖 | docker.service |
| 端口 | 9900（`AUTOTEST_PORT`） |

**恢复步骤**：
```bash
# 需要先把代码仓库 clone 到 ~/code/imfl_auto_test
sudo cp templates/systemd/imfl-autotest.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now imfl-autotest
systemctl status imfl-autotest
```

**⚠️ 该单元 `WorkingDirectory` 和 `EnvironmentFile` 都是绝对路径**，新机用户名不同需改。

## 4. privoxy（8118）

遗留 HTTP 代理，监听 `127.0.0.1:8118` 与 `[::1]:8118`。

**注意**：`~/.proxy.sh` 的清理逻辑会把 git 中指向 `:8118` 的分节删掉
（视为废弃端口）。若新机不需要 privoxy，**可跳过**。

## 5. Antigravity IDE remote server

| 项 | 值 |
|---|---|
| 目录 | `~/.antigravity-ide-server/` |
| 二进制 | `~/.antigravity-ide-server/bin/2.5.5-<hash>/` |
| 日志 | `~/.antigravity-ide-server/data/logs/<时间戳>/` |
| 端口 | 动态分配（实测曾用 43067） |

**⚠️ 它跑在 WSL 内，`wsl --shutdown` 会杀掉它**（需在 IDE 里重连，会自动拉起）。

**已知报错**（代理问题导致）：
```
Error: Client network socket disconnected before secure TLS connection was established
```
**这不是 DSH 插件造成的**。根因是编辑器 remote server 注入的幽灵代理
（见 `intent/wsl.md` 的「幽灵代理陷阱」）。修复：确保 `~/.proxy.sh` 与
`wsl-proxy-autofix` 正常，然后重连 IDE。

## 服务启动顺序（重要）

```
Windows 代理软件启动（星连/Clash，端口 7897）
   ↓
WSL 启动 → fix-wsl-net.service 修正路由
   ↓
~/.bashrc → source ~/.proxy.sh → proxy_on（探测并设置代理）
   ↓
litellm 启动（4001）← 需要 proxy.env 的密钥
   ↓
ccp use <profile>（生成 env.sh，指向 127.0.0.1:4000）
   ↓
各 AI CLI 可用
```

**排查思路**：任何 CLI 卡住，从**最上游**查起（代理 → 路由 → litellm → ccp）。
