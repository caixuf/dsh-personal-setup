# 证据边界（Evidence Boundary）

## 为什么存在

**已发生的真实事故**（不是假设）：

1. **WorkBuddy 缺模型**：读了插件源码 + 作者注释（"这条正是根因"），据此断言"凭据 ref 键名不匹配"，给了完整证据链。**实际原因只是设置页一个开关**，而答案就写在 `state.json` 里，那个文件一次都没打开。
2. **R6 编译失败**：读了 handover 文档里的推断（"profile 缺 `os.platform`"），照它试了 3 种变体全败。**实际是 `subst` 子串替换把 `PROJECT_TAG` 写成了 `_im_im`**。推翻它只需一条命令：`grep os.platform */conaninfo.txt`。

**共同病根**：把「文档/代码里写的」当成「实际是什么」。**读代码和读文档是同一份材料，复述三遍不等于验证三遍。**

## 核心规则：每条结论标注证据等级

| 等级 | 含义 | 必须附带 |
|---|---|---|
| `observed` | **实际执行过** | 命令 + 原始输出（可复跑） |
| `read` | 只读了代码/文档/配置 | `文件:行号` |
| `inferred` | 推理得出 | 推理链 **+ 明确标注未验证** |

**禁止**把 `read` / `inferred` 表述成 `observed`。

- ❌ "根因是 X"（实际只读了代码）
- ✅ "**read**：代码 `a.js:42` 写的是 X。**未实测**。"
- ✅ "**observed**：`grep -c foo bar` → `0`，故 X 不成立。"

## 判定：这是真阻塞还是假阻塞

**真阻塞会带证据，假阻塞只给结论。**

- **真阻塞**：能列出试过的路径 + 具体报错，且报错指向**同一堵墙**
- **假阻塞**：结论很确定，但拿不出一次真实的失败尝试

## 红线：同一假设的 N 个变体全失败 → 换假设

连续 **2 次**失败后，停下来问：**我是不是在同一个错误前提上打转？**

> 真实案例：R6 那次"补 `os.platform`"试了 3 种（移 cache / 注入 profile / 镜像级修），
> 全是同一假设的变体。**"试了 3 种均无效"不是努力，是假设错了的信号。**

## 找 delta，不要找"什么坏了"

用户说"**以前是好的**"时，先假设**"什么都没坏，是世界变了"**，去找那个变量。

1. 先证明**什么没变**（版本？镜像？依赖？）—— 数量有限，好验证
2. 剩下的唯一变量就是嫌疑
3. 再回到"什么坏了"

> 真实案例：R6 靠比对"绿的任务 vs 红的任务"三个变量（mf_system / 镜像 / MFF），
> 发现**唯一 delta 是 MFF 换了提交**。结论：不是旧修复失效，是撞上了新墙。

## 裁决词表（不允许模糊表述）

下结论时必须落在其中之一：

| 裁决 | 含义 |
|---|---|
| `VERIFIED` | 端到端实测通过，附命令与输出 |
| `FIX_READY` | 改动已就绪，**但未验证** |
| `NEEDS_MORE_EVIDENCE` | 缺关键证据，**说明缺什么** |
| `BLOCKED_BY_ENVIRONMENT` | 环境阻塞，附具体报错 |
| `DISPROVEN` | 某假设被实测推翻，附证伪命令 |

**禁止输出**："应该可以了" / "大概率是" / "理论上没问题" / "基本确定"。

## 改之前

- **隔离现场**：改动前把要动的东西**移到备份目录**（不是 `rm`），保证可回退
- **验证语义**：改配置/规则类文件前，先在**临时文件**里跑对照实验，
  证明新写法**既修好目标，又不破坏现有行为**
- **改完必须端到端验证**：用**与失败时完全相同的参数**重跑，不是"看起来对"

## 汇报模板

```
结论：<VERIFIED|FIX_READY|NEEDS_MORE_EVIDENCE|BLOCKED_BY_ENVIRONMENT|DISPROVEN>

observed:  <命令> → <原始输出摘要>
read:      <文件:行号> → <内容>
inferred:  <推理> （未验证）

未验证的部分：<明确列出>
下一步：<具体动作或需要用户决策的选择>
```

## 收尾

- **不确定就说不确定**，并说明"怎么才能确定"
- **缺证据时给 `NEEDS_MORE_EVIDENCE`**，不要猜
- 结束回合时**留下下一步的选择**，不要只说"我不做 X"
