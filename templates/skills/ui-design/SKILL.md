# 界面设计（UI Design）

## 为什么存在

**已发生的真实失败**（2026-10-12 一次会话内）：

| 我做的 | 为什么是错的 |
|---|---|
| 让用户把壁纸雾层调到 `lightFog 65-75` | **凭感觉给的数字。** 没算对比度，没问用户要多浓 |
| 用户说「字体颜色很重要，不同壁纸下可见效果不同」 | **完全没接住。** 那是设计诉求，我当成了功能问题，继续查插件 |
| 挑主题插件时看「月下载 + 有没有 contrast guard」 | 下载量是**采用度**，不是**好不好看** |
| 换掉 skin-center，理由是「设置项找不到 + 静默失败」 | 功能理由。**从头到尾没人问过它好不好看** |
| 用户发壁纸截图说正文字可读、顶栏字发灰 | 我看到了，**但到最后也没真正解决** |

**共同病根：我没有审美坐标系，却表现得像有。**

**这条 skill 治的不是"审美能力"，是"不许假装有"。**

## 红线一：禁止凭感觉给数值

❌ **禁止**：「调到 65-75 应该差不多」「大概 40% 比较合适」

✅ **必须**：给出**计算依据**或**明确说不确定**。

需要数值时，先算或先查：

```bash
# 对比度：正文至少 4.5:1，大字（≥18px 或 ≥14px 粗体）至少 3:1
# 这是 WCAG 2.1 AA 标准，不是我的审美
```

若算不出，就**明确说**：「这里我给不出可靠数值，需要你定，或给我一个参照」。

## 红线二：先声明标准，再动手

做任何界面改动前，**先输出这四项**（可简，但不可省）：

```
1. 目的：谁在用这一屏？核心动作是什么？
2. 层级：什么必须最显眼？次要的是什么？再次要的是什么？
3. 约束：浅色底还是深色底？信息密度要多高？
4. 不确定项：哪一处我判断不了、需要你定？
```

**第 4 项是重点。** 写不出"我不确定"，说明在硬撑。

## 红线三：涉及"好不好看"，不许我独自决定

| 情况 | 我必须做的 |
|---|---|
| 用户说「太丑/不好看/不协调」 | **先问具体哪里**，不要自己猜着改 |
| 需要选配色/风格 | **给 2-3 个候选 + 各自特点**，让用户选 |
| 用户描述了一个产品（"像 Linear 那样"） | **提取它的设计体系**再套用，不凭印象模仿 |
| 我认为某个方案更好 | 说理由，但**让用户拍板** |

**有参照物时优先提取，不靠想象。** 见下方「工具」。

## 对比度：能算就算

这是唯一「审美可以量化」的地方，别放过：

| 场景 | 门槛 |
|---|---|
| 正文 / 小字 | **4.5 : 1** |
| 大字（≥18px，或 ≥14px 加粗） | **3 : 1** |
| 图标、边框等非文字元素 | **3 : 1** |

**实测方法**（不要目测）：

```js
// 相对亮度与对比度
function lum(hex){const c=hex.match(/\w\w/g).map(x=>parseInt(x,16)/255)
  .map(s=>s<=0.03928?s/12.92:((s+0.055)/1.055)**2.4);
  return 0.2126*c[0]+0.7152*c[1]+0.0722*c[2]}
function ratio(a,b){const[x,y]=[lum(a),lum(b)].sort((p,q)=>q-p);return (x+0.05)/(y+0.05)}
```

**壁纸/渐变背景**：单点对比度算不准 —— 文字可能落在最亮或最暗处。
此时要么铺半透明遮罩（算出遮罩所需的 `alpha`），要么给文字加 `text-shadow`
（业界标准做法：Instagram / 微信 / B 站都在用），**不要靠"看起来还行"**。

## 工具：需要参照物时

```bash
# skillui —— 从任意网站/项目反向提取设计体系
# （配色、字体、间距、动画、组件 → .skill 文件）
npx skillui <网址或仓库路径>
```

**用法**：用户说「想要 X 那种感觉」→ **提取 X 的实际设计体系** → 套用。
**不要凭印象模仿。**

## 交付时必须说清

界面任务交付时，明确标注：

- ✅ 哪些是**实测过对比度**的
- ⚠️ 哪些是**我按标准推的**（给出行号/标准条款）
- ❓ 哪些是**我判断不了的，需要你看一眼**

**"应该挺好看的"不是交付语。**

## 与 evidence-boundary 的关系

| skill | 管什么 |
|---|---|
| `evidence-boundary` | 结论**真不真**（实测 vs 推断） |
| `ui-design` | 决定**好不好**（有没有标准、有没有瞎猜） |

**两者同源**：都是「不许拿不确定的东西当确定的东西」。
证据边界管事实，设计边界管审美 —— **两者都是因为我不会就承认，而不是不会装懂。**

## 判定：我是不是在用审美掩盖不会？

出现这些信号，停下来：

- ❌ 我给的数值没有计算过程
- ❌ 我说"更好看"但说不出**好在哪、依据是什么**
- ❌ 用户提了视觉问题，我答的是技术问题
- ❌ 我连续两次调整视觉，用户仍不满意 —— **说明方向错了，不是幅度不够**
- ❌ 我在用「下载量高」「用户多」代替「好看」
